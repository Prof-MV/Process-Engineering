19.2 Lab 1 — Logic Thinking for Robot Control: LightBot & Rocksi

An introduction to programming logic — sequencing, loops and conditionals — and to programming a robot arm, using two free browser simulators: LightBot (a puzzle game that teaches sequence/loop/conditional thinking) and Rocksi (a browser, block-based simulator for a collaborative robot arm — Scratch-style blocks, no install or login). The focus is on optimising the number of programming steps.

AI use: not permitted — the outcome is your own logic. Lab 14 returns to a real 6-axis arm in RoboDK for Web.

19.2.1 Learning outcomes

After this lab you should be able to:

  • Explain why programming logic matters for reliable, safe, repeatable automation.
  • Use sequences, loops and conditionals to solve a control problem with the fewest steps.
  • Describe the role of a teach pendant (jogging, teaching points, deadman/E-stop, reduced-speed teach mode, I/O testing).
  • Program a simple pick-and-place-style sequence on a block-based robot simulator.

19.2.2 Prep work

  • Read the Programming Logic handout (importance of programming logic; loops; conditionals; teach pendants).
  • Watch: Rocksi robot simulator: Meet Sawyer.

  • Check that LightBot and Rocksi load on your device.

19.2.3 Materials & equipment

  • Computer or tablet with internet access — one per student (this is an individual lab)
  • Access to LightBot (browser, free — the “Code Hour” version needs no login)
  • Access to Rocksi block-based robot-arm simulator (browser, free, no login)
  • Lab worksheet (provided — the questions are reproduced in the Procedure below)

19.2.4 Procedure

Part 1 — Programming logic with LightBot

  1. Sequencing. Complete the first levels. Worksheet: describe the sequence of commands you used to complete Level 1. (1 mark)
  2. Loops. Complete levels that require loops. Worksheet: how did using loops let you complete the level more efficiently? (2 marks)
  3. Conditionals. Complete levels that use conditional commands. Worksheet: give an example of a conditional you used and explain its purpose. (2 marks)
  4. Challenge — maximum level & optimisation. Reach Level 15 with the minimum number of steps. Worksheet: describe your strategy and how you optimised. (2 marks)

Part 2 — Programming a robot arm with Rocksi

  1. Basic movements. Move the robot to several positions. Worksheet: describe the steps to move the robot to Position A. (1 mark)
  2. Programming a sequence. Program a sequence of moves using Rocksi’s blocks. Worksheet: list the command sequence you used. (1 mark)
  3. Simulating inputs & outputs. Simulate an I/O to troubleshoot a robot operation. Worksheet: explain how you simulated the I/O and its effect. (1 mark)

Finish each part with a short reflection on how the skills apply to engineering design and safety.

19.2.5 Deliverables & submission

Completed worksheet (all questions above plus the two reflections), submitted on FOL by the end of the lab period. Assessment is based on task completion in both simulators and the quality of the written answers.

19.2.6 Rubric

From the handout’s marking table — 10 marks total:

19.2.7 Instructor notes

  • Prep: confirm both simulators are reachable through the lab network/firewall the day before — LightBot and Rocksi are third-party sites and are the single point of failure for this lab. Have an offline fallback (screenshots / a slide walk-through) ready.
  • Individual lab — one machine per student; no group submission.
  • Marking: award loop/conditional marks for explanation, not just level completion. For the challenge task, ask for the step count as evidence of optimisation.

19.3 Lab 2 — Engineering Design Process Documentation

You produce the engineering-documentation package that a real project needs to move a design into production — specification sheets, a bill of materials, a task list / process flow, a project schedule and Gantt chart, a production-facility layout drawing, and a health-safety-environment (HSE) risk assessment — for the Précitech Components shaft-kit assembly cell described in the case study below. The same cell is simulated in Lab 3, so the documents you build here feed directly into the next lab. Tools: Microsoft Visio/Word, Project and Excel.

AI use: not permitted for any part of the report.

NoteCase study — Précitech Components: new shaft-kit assembly & packing cell

Précitech Components is a Tier-1 automotive supplier in Granby, Québec. Its CNC turning cells produce transmission shaft blanks (AISI 4140 steel, Ø 25.000 mm ± 0.050 mm) for a major OEM customer. The OEM now wants the shafts delivered as a ready-to-install kit rather than as loose blanks, so Précitech is adding a manual kitting, sub-assembly and packing cell immediately downstream of the CNC turning cells.

One shaft kit contains: 1 machined shaft blank, 2 tapered roller bearings, 1 retaining ring, 1 lip seal, 1 dowel pin, 1 desiccant sachet — placed in a moulded tray inside a labelled carton.

Target output: 250 kits/day on one 8-hour shift.

Process outline: finished blanks arrive from the CNC cells on a trolley; bought-in components (bearings, rings, seals, pins) are held in a small storage rack that is replenished from the main warehouse when stock falls to a reorder level; an operator picks the components for one kit, presses the two bearings onto the shaft, fits the retaining ring and lip seal, inspects the assembly against a checklist, places it in a tray, closes and labels the carton, and stages it for the shipping dock.

Plant manager Sophie Tran has asked your team to produce the engineering documentation package for this cell before it is built.

This is the same plant used in the machine-learning labs (Labs 7–12), which build a predictive-maintenance proof of concept for Précitech’s CNC turning cells.

19.3.1 Learning outcomes

After this lab you should be able to:

  • Explain terms such as HSE, Basic Engineering Design Data (BEDD), Front-End Engineering Design (FEED), fast-tracking, project schedule and General Arrangement (GA) drawing.
  • Produce a specification sheet and a bill of materials for a manufactured product.
  • Build a task list / process-flow chart with durations and turn it into a project schedule and Gantt chart in Microsoft Project.
  • Draft a production-facility layout drawing showing product in/out, stations, storage, and material and people flow, and mark starvation / blockage risk points.
  • Complete an HSE risk assessment for a manual assembly cell.

19.3.2 Prep work

  • Read the case study above and Unit 2 content on the basics of process engineering and design.
  • Skim the Design Documentation supplement for the document templates and the detail-design / engineering process-flow diagram (ignore the popsicle-bridge framing — the document types are the same).
  • Confirm you can open Microsoft Visio/Word, Project and Excel on a lab PC.
  • Form teams of 2–3.

19.3.3 Materials & equipment

  • Lab PC with Microsoft Word / Visio, Microsoft Project, Microsoft Excel
  • Templates from FOL:
    • Bill_of_Materials_Template_for_Excel.xlsx
    • Gantt_chart.mpp (Microsoft Project example file)
    • HSE risk-assessment Word template (Risk assessment template)
  • The Précitech shaft-kit case study (above) — the single source of requirements

19.3.4 Procedure

Phase 1 — Specification sheet & bill of materials. Write a specification sheet for the shaft kit (customer, part number, contents, key dimensions and tolerances, packaging, marking, applicable standards) and a specification sheet for at least one bought-in component (e.g. the tapered roller bearing). Fill in the Excel BOM template for one complete kit — every item, quantity, unit and source (machined in-house vs. purchased).

Phase 2 — Task list / process flow. Build a chronological task list for producing one kit: receive blanks → store components → pick components for one kit → press bearings → fit retaining ring and seal → inspect → place in tray → close and label carton → stage for dock. Add a column for the time each task needs. Use the task-numbering scheme (Task 1 → Sub-task 11 → Sub-sub-task 121…) from the supplement. Draw the flow as a chart in Visio or Word.

Phase 3 — Project schedule & Gantt chart. Open the example .mpp file, enter the tasks and durations for standing up the cell (procure racking and fixtures, install bearing press, set up inspection station, write the SOP, train operators, run a pilot batch), and generate a schedule and Gantt chart.

Phase 4 — Production-facility layout drawing. From the task list, allocate space for each activity and draw a General Arrangement of the kitting cell. Show: product in (blanks) and product out (kits), component storage rack, assembly station(s), bearing press, inspection station, packing bench, staging area, and the raw-material, finished-goods, waste and people-movement flows. Mark where material starvation (components not replenished in time) and material blockage (finished kits not removed) could occur. Discuss with your team and the instructor and get signed off.

Phase 5 — HSE risk assessment. Identify at least five health-and-safety risks in the cell — for example manual handling of the blank trolley, pinch points at the bearing press, sharp edges on retaining rings, repetitive assembly motion, and the carton knife — and document each in the risk-assessment template (hazard, who is harmed and how, current controls, further action, owner, deadline, done).

19.3.5 Deliverables & submission

One report containing all five deliverables: specification sheets + BOM, task list / process-flow chart, Microsoft Project schedule + Gantt chart, facility layout drawing, and the completed HSE risk assessment. Keep the electronic layout drawing — you refine and reuse it in Lab 3. Submit on FOL by the end of the lab period.

AI tools may not be used for any part of the report.

19.4 Lab 3 — Manufacturing Facility Design & Simulation (AnyLogic)

You turn the Précitech kitting-cell layout from Lab 2 into an electronic drawing, then use AnyLogic Personal Learning Edition to run a discrete-event simulation of the cell’s order-fulfilment behaviour. By changing order and replenishment parameters and reading the statistics screens, you see how component-stock policy drives waiting time, picking (kitting) time and throughput.

AI use: not permitted for any part of the report.

19.4.1 Learning outcomes

After this lab you should be able to:

  • Produce an electronic facility layout showing stations, storage, flows, manual vs. automated stations, and starvation / blockage risk points.
  • Run an AnyLogic model, change input parameters, and capture the statistics output.
  • Interpret order statistics (preorder waiting time, picking time, full processing time, order states) and goods statistics (unavailable goods, stored reserved / unreserved goods, storing time) and explain how they are linked.
  • Explain how simulation supports facility-design decisions such as where to hold buffer stock and how often to replenish.

19.4.2 Prep work

  • Re-read the Précitech case study and review Unit 3 content on integrated manufacturing systems.
  • Read the Facility Simulation supplement (order statistics, goods statistics, and the relationships between them).
  • Watch the AnyLogic walk-through video (link on FOL).
  • Install AnyLogic Personal Learning Edition (free) on your machine before the lab and confirm it launches.
  • Bring your Lab 2 layout drawing, spec sheets, schedule, BOM and flow documents.

19.4.3 Materials & equipment

  • Lab PC with AnyLogic Personal Learning Edition and Microsoft Visio/Word/Project/Excel
  • The AnyLogic order-fulfilment / warehouse demo model referenced in the video — confirm the exact model and stage it on FOL / the lab PCs
  • Your Lab 2 documents for the Précitech kitting cell

Phase 1 — Facility drawing. Recreate your Lab 2 kitting-cell layout electronically (Visio or equivalent). Work through the checklist and record your findings: product in/out shown? work-sequence task list with timings? tools and component bins shown? component (raw-material) flow? finished-kit flow? waste-material flow? people-movement flow? how many stations, and are any automated (e.g. the bearing press)? where could component starvation occur? where could finished-kit blockage occur? are storage / assembly / inspection / packing / staging / social areas identified? 19.5 Lab 4 — Lean: Value Stream Mapping, Takt and Pull

You map the Précitech shaft line as it runs today, size it against customer demand, and redesign the flow. Working in draw.io (browser) you build a current-state value stream map; in Google Sheets you compute takt time, an operator balance chart and process cycle efficiency; and on AnyLogic Cloud (browser, free public tier) you compare push, pull and a kanban-capped supermarket. You finish with a future-state map carrying one SMED and one pull improvement. Everything runs in a browser — nothing to install.

AI use: permitted with disclosure, but not for the map itself or the takt / PCE calculations — those must be your own work. Name any tool you used and what for.

19.5.1 Learning outcomes

After this lab you should be able to:

  • Draw a current-state value stream map from a station data table, with a material-flow line, an information-flow line and a lead-time ladder.
  • Compute takt time from customer demand and compare it against station cycle times on an operator balance chart to find the bottleneck.
  • Classify observed waste against the seven wastes and compute process cycle efficiency (value-added time ÷ lead time).
  • Explain how push, pull and a kanban-capped supermarket differ in WIP and lead time, using simulation output as evidence.
  • Propose a future state and justify the projected lead-time reduction.

19.5.2 Prep work

  • Read Chapter 5 (Lean) on takt time, the seven wastes, pull systems, kanban and SMED, and the Chapter 3 material on line balancing.
  • Create a free draw.io document (“Device” storage is fine, no account needed) and skim the built-in Value Stream shape library.
  • Confirm AnyLogic Cloud loads and that you can run a public model and edit its input parameters in the browser.
  • Download vsm_station_data.csv from FOL — the station table for the Précitech shaft line (cycle time, changeover, uptime, WIP, batch size per station).
  • Form teams of 2–3.

19.5.3 Materials & equipment

  • Computer with internet access; one per team is enough, one per student is better
  • draw.io (browser) — current- and future-state maps
  • Google Sheets (browser) — takt, balance chart, PCE
  • AnyLogic Cloud (browser, free public tier) — push/pull model
  • vsm_station_data.csv from FOL
  • The Précitech case study — demand is 250 kits/day on one 8-hour shift

19.5.4 Procedure

Run the setup step first: open vsm_station_data.csv in Google Sheets and read the column headings so you know what each station contributes.

Task 1 — Current-state value stream map (30 min). In draw.io, map the shaft line end to end: CNC turn → deburr → wash → inspect → the Lab 2 kitting cell → shipping. For each process box record cycle time (C/T), changeover time (C/O), uptime and batch size from the supplied table; put an inventory triangle with the WIP count between each pair of boxes; add the supplier and customer, the production-control box, and the information-flow arrows (forecast, daily order, schedule). Draw the lead-time ladder along the bottom — processing time on the lower step, inventory wait time (WIP ÷ daily demand) on the upper step — and total it to a production lead time and a value-added time. (3 marks)

Task 2 — Takt and the balance chart (20 min). In Sheets, compute takt time = available shift time ÷ customer demand for the 250 kits/day target (state your planned/unplanned downtime assumption). Build an operator balance chart — one bar per station, station C/T on the y-axis, a horizontal takt line across all bars. Name the bottleneck station and say by how much it exceeds takt. (2 marks)

Task 3 — Waste and process cycle efficiency (25 min). Walk the map and classify every wait, move and rework against the seven wastes (transport, inventory, motion, waiting, overproduction, overprocessing, defects) — at least one concrete example per waste that is present. Compute process cycle efficiency = value-added time ÷ production lead time from your Task 1 ladder, and state whether the line is “lean” by the usual 25 % rule of thumb. (2 marks)

Task 4 — Push vs pull on AnyLogic Cloud (25 min). Open the supplied push/pull model on AnyLogic Cloud. Run it three ways, changing only the control policy: (a) push — every station runs whenever it has parts; (b) pull — downstream withdrawal triggers upstream; (c) kanban-capped supermarket — a fixed WIP cap between the bottleneck and its predecessor. For each run record average WIP and average lead time from the model output, in a small Sheets table. (2 marks)

Task 5 — Future-state map (20 min). In draw.io, redraw the line with one SMED change (halve the changeover at one station and justify the halving) and one pull change (a supermarket or FIFO lane where you had push). Recompute the lead-time ladder and state the projected lead-time reduction and which of the seven wastes each change attacks. (1 mark)

19.5.5 Deliverables & submission

One team report (PDF) containing: the current-state VSM (draw.io export), the takt calculation and operator balance chart, the seven-wastes table and the PCE calculation, the push/pull/supermarket results table with a two-sentence interpretation, and the future-state VSM with its justification. If you used an AI tool for anything permitted, add a one-line disclosure. Submit on FOL by the end of the lab period.

19.5.6 Rubric

10 marks total.

Deliverable Marks

19.6 Lab 5 — Ergonomics in Automated Manufacturing (REBA & Inseer)

You assess three workplace tasks for musculoskeletal risk two ways: manually with the REBA (Rapid Entire Body Assessment) worksheet, and automatically with Inseer, an AI video-based ergonomic-assessment tool. You then compare the two methods.

AI use: permitted with disclosure. Note that Inseer is itself an AI tool and is required for this lab — that is a lab instrument, not a generative AI writing your report.

19.6.1 Learning outcomes

After this lab you should be able to:

  • Explain why ergonomics matters in an automated manufacturing facility and name common ergonomic risks and their effects on workers.
  • Score a task with the REBA worksheet and interpret the result.
  • Generate an ergonomic risk-assessment report with Inseer.
  • Compare manual vs. automated assessment — advantages and limitations of each.

19.6.2 Prep work

  • Review the introduction-to-ergonomics and REBA material (video links in the handout, Procedure topics 1–2).
  • Skim the REBA step-by-step guide and the REBA Employee Assessment Worksheet.
  • Form groups of 3–4.

19.6.3 Materials & equipment

  • REBA Employee Assessment Worksheet (printed, one per student/group)
  • Inseer software tool — web-based; account/login required
  • Computer with internet access
  • Sample tasks from an automated manufacturing facility (videos / photo sets):
    • Task 1 — lifting boxes repeatedly
    • Task 2 — computer-workstation setup
    • Task 3 — floor cleaning with a buffer

19.6.4 Procedure

  1. Intro to ergonomics — watch the overview videos (importance; common risks and impacts).
  2. Overview of REBA — watch how to use the worksheet.
  3. Task evaluation — each group is assigned one of the three tasks. Observe and analyse it, note ergonomic risks (repetitive motion, awkward posture, heavy lifting, vibration, glare, chair height …), score it with the REBA worksheet, and interpret the score.
  4. Intro to Inseer — overview of the tool; input the task data and generate a risk-assessment report.

19.15 Lab 13 — TPM/OEE, Root Cause and a New Dataset

You bring the whole term together on one problem: a Précitech CNC turning cell that is not making its numbers. You compute OEE from a shift log and split the losses into the Six Big Losses; you Pareto the failure modes; you run a 5-Why and Ishikawa root-cause analysis; and then you direct an LLM to build a failure classifier on a new dataset — the AI4I 2020 Predictive Maintenance Dataset from the UCI repository (CC BY 4.0, 10 000 rows, 5 labelled failure modes). 19.15.1 Learning outcomes

  • Direct an LLM to build and evaluate a classifier on an unfamiliar, class-imbalanced dataset, and choose metrics that survive the imbalance.

  • Computer with internet access
  • Google Sheets — OEE calculation and the Pareto chart

19.15.4 Procedure

Task 1 — OEE and the Six Big Losses (25 min). (2 marks) From precitech_shift_log.csv, compute availability (run time ÷ planned production time), performance (ideal cycle time × total count ÷ run time) and quality (good count ÷ total count), then OEE = the product. Take each downtime and loss entry in the log and assign it to one of the Six Big Losses (breakdowns, setup & adjustment, small stops, reduced speed, startup rejects, production rejects). State which Big Loss is costing the most OEE points.

Task 2 — Pareto the failure modes (20 min). (1 mark) In the AI4I data, count how many rows carry each of TWF, HDF, PWF, OSF and RNF. Build a Pareto chart in Sheets (bars descending, cumulative line). Identify the vital few failure modes that account for most of the failures, and note where RNF sits and why that matters.

Task 3 — 5-Why and Ishikawa (25 min). (2 marks) Take the top failure mode from Task 2. Run a 5-Why chain and draw an Ishikawa diagram in draw.io with the six standard bones (machine, method, material, measurement, man, environment). Use the measured feature columns as evidence on the bones — for example, compare tool wear, torque, rotational speed and the air-vs-process temperature gap for the failing rows against the healthy rows, and put the numbers on the diagram.

Task 4 — Direct an LLM to build a failure classifier (35 min). (4 marks) In Colab, prompt an LLM to build a classifier that predicts the machine-failure flag from the five process features. You are transferring the capstone workflow, not its code — this is tabular classification, not time-series RUL regression. Report a confusion matrix and precision and recall for the failure class. The failure rate in AI4I 2020 is about 3.4 %, so accuracy is a useless metric here — a model that predicts “no failure” every time scores ~96.6 % accuracy and catches nothing. State explicitly which class-imbalance trap you hit and how you detected it. That is the lesson of this task.

Task 5 — 8D D4/D5 (15 min). (1 mark) Write the “D4 — root cause” and “D5 — permanent corrective action” sections of an 8D report for the top failure mode. Tie the model’s feature importances back to specific bones on your Task 3 fishbone, and propose a corrective action that a TPM programme could actually carry out (an autonomous-maintenance check, a setup standard, a condition limit).
